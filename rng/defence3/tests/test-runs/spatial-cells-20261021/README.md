# Spatial-cell sweep — 2026-10-21

Stopped at the user's request after completing 1×1, 2×2 and 4×4 at 4M starting units. The 8×8 run was interrupted during its first warmup; it has no completed timing result. No reverse-order repeats were started. The sweep and child benchmark were stopped, and a process query confirmed no matching 8×8 benchmark remained.

The production constant remains `CHUNK_SIZE = 1`. `tests/checkerboard-tps.bench.cjs --chunk-size=N` creates a per-run data-static source fixture rather than editing production. This experiment changes spatial index granularity only; no local-coordinate compression was implemented.

All runs use the ordinary production WASM binary, seven real helpers, a 1000×1000 map, groups of 32 per owner, 125,000 starting opposing mixed towers, three warmups and 16 measured ticks. Rendering and transport are absent. Ordinary combat/deaths, GC, paging and scheduling remain included. Runs and validation were serial.

Pair and acquisition thread-ms are sums of elapsed kernel intervals across all participants, including stalls; they are not tick wall times or hardware CPU cycles. Index collection includes its stage wait. Larger cells save metadata but increase measured contact and acquisition work. The single-pass tick times worsen 5.0% and 13.2%; no repeated-run significance claim is made. Different traversal/contact order changes survivors, so these are different layout variants rather than identical-work replays.

Smoke runs pass at sizes 1, 2, 4 and 8. At each of 2, 4 and 8, `spatial-index-builds.test.cjs` passes serial-versus-parallel query comparisons on three chaotic map types; `shared-spatial-determinism.test.cjs` passes 4,200 active units with 0 versus 7 real helpers and a mid-run snapshot restore. Six targeted regression files pass. Logs and fixtures remain beside the results.

`comparison.json` / `comparison.md` are generated by `tests/compare-spatial-cells.cjs`; raw JSON, CPU profiles, all-thread traces, paging logs and analyses are retained. `tests/spatial-cell-sweep.ps1` reproduces the sweep, but it was explicitly stopped here and is not scheduled to resume.

`occupancy-memory.json` contains arithmetic estimates for the subsequent occupancy-grid discussion. At eight cells per tile axis (4-pixel cells), a 1000×1000-tile map has 64 million cells: one bit plane is 7.63 MiB, a byte counter plane 61.04 MiB, a uint16 counter plane 122.07 MiB, and a uint32 owner plane 244.14 MiB. Multiply by the required collision layers, team-specific planes or buffers. No occupancy-grid implementation or performance benchmark has been run.
